No legacy type was deleted, moved or deprecated. Existing Banking2/Simulation1/Valuation1 and adapter1 contracts are retained. The concrete gap was legacy simulation history's financial-day cursor without a returned day or next cursor. New `EconomicSimulationHistory`1 is independent of that facade. `ServerServices.simulationHistory()` admits the existing sealed owner grant on the owner thread, requires READY foundation storage and rechecks session/world ownership on the storage worker. It returns an empty Optional for denied access, versus a present empty Page for a legitimate empty history.

`SimulationHistory.page` uses one SELECT-only transaction with current-world filtering, saved window/plan metadata and immutable journal fact/version binding. At most17 rows provide limit1–16 plus lookahead. It preserves the original record version, day/boundary, identities, hashes, prime/FX maps and exact ratio. It creates no schema, journal, scheduler or clock change. New DTO collection components are defensive copies and contain no SQL, client or simulation-domain types. Foundation Grant remains a disclosed existing authority parameter.

The compiled example obtains `PartyAuthorization.player` from the current ServerPlayer and active world, then checks current player object, services, session, world and caller view before displaying through the server executor. Its returned action abandons display only. It is a copyable consumer class, not an installed command, network handler or event listener. It is compile-checked rather than claimed as a new native authentication witness; existing owner factory and A10-04 authentication evidence remain applicable.
