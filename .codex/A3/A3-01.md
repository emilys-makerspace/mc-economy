# A3-01 parties and authorization

Verified. A3 owner references pair the financial-world ID with a typed player,
system or reserved organization owner. Player identity retains the Minecraft
UUID. Server admission resolves the actor from the live Minecraft sender or
trusted built-in context and binds a detached capability to the active session.

Scoped journal requests derive the actor and reserve `economy:owner` in
canonical data. The existing journal checks current admission before replay,
lookup and uncertain-commit disclosure. The inspection receipt is a versioned
journal fact carrying the target owner, with the operator UUID, world, UTC and
sequence in the envelope. It contains no account data and needs no migration.

A3-02 can use the owner-bound journal entry points and must check actual account
ownership under its transaction. A3-04 must commit an inspection receipt for
each logical inspection before disclosure and recheck the current audience and
authorization at publication. Use a new operation ID for each fresh inspection.
Reissue authority from the live sender for each attempt. Inspection supports
player-backed operator commands so audit identity is a Minecraft UUID.
