Java 21, Minecraft 1.21.1, NeoForge 21.1.252.

- DepositsTest verifies 24-slot grouping, per-source floor rounding, one
  committed credit on replay, all-skipped zero-credit returns, mixed payable
  and skipped originals, exact component retention and quantity conservation.
- Stale FX, account and terminal revisions reject settlement. Lost live
  authority denies it. ATM coin input rejects before reservation. Close and
  page-change cancellation preserve original quantities.
- Partial-capacity return admits three items, confirms two saved deliveries
  and creates one existing Custody claim for the two original items left.
  Repeated completion returns the original result and does not create
  another claim. Quantity protection transfers atomically to custody.
- Restart after an unproven disconnect quarantines the reservation and its
  exact originals into a custody review case, retaining locks with no
  collectible claim or bank credit.
- A preinserted return row injects a real SQLite constraint failure after
  settlement preparation. Recovery verifies the original saved reservation,
  no credit, no cash consumption and no operation outcome. Original-ID retry
  succeeds after removing the fixture fault.
- Compensation of a protected return claim credits the verified loss once,
  retires the original issued quantity and releases its protection.
- Oversized canonical preview input rejects before physical movement.
- Targeted cash, custody, journal/migration, backup and WAL checks passed.
- Final full offline build passed, plus client task help and dry-run.

Two isolated Minecraft server runs under build/a5-05-deposit-acceptance and a
separate build/a5-05-deposit-restart copy reached READY, loaded the mod/driver,
saved all dimensions and recorded normal clean shutdowns. The actual
DepositInventory fixture snapshots 24 marked ItemStacks, moves originals into
player persistent custody, returns two items into partial capacity, retains
two, reloads PlayerDataStorage and proves return-attempt replay adds nothing.
The completed fixture also verifies retirement of consumed originals and
rejects returning them. DEPOSIT_INVENTORY_PASS was emitted.

The isolated client under build/a5-05-deposit-client loaded Economy, SQLite,
the client entry point and rendering resources. It was intentionally
interrupted after loading, exit 130. No user worlds were used.

The first compilation exposed a missing List import. A stale-account fixture
also attempted to decrease a revision, which the account trigger correctly
rejected. The fixture was changed to continue from the newer revision.
Subsequent checks passed.

The original interrupted tool call was not executed because automatic
approval review hit a usage limit. Work resumed after the user requested
continuation. The inventory adapter was then written, compiled and tested.

Limits remain explicit. Final client menus, actual close/page/disconnect event
wiring and terminal geometry are excluded. Their cancellation/recovery
decisions are exercised through the server APIs. Live inventory checks
exercise the physical adapter and real save/load, while SQLite fixtures
exercise financial composition and evidence admission. No machine power loss
or forced Minecraft process termination was performed in this package.

Two economy workers owned deposit core/schema and return lifecycle
respectively. Main owned integration, cross-workflow quantity protection,
physical inventory adapter and all Gradle/game checks.
