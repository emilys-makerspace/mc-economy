## Ownership

`Economy` owns an identity-keyed service map, one entry per MinecraftServer. Starting,
post-tick and stopping events run on the server thread. Stopping removes the entry.
No client classes are referenced by common code. `EconomyClient` is CLIENT-only.
`ServerServices` captures its owning thread and assigns a fresh session UUID; no static
world state exists. Readiness is published by a server tick after initialization.
Requests reject immediately unless READY, including before initialization and after stop.
Initialization exceptions cause UNAVAILABLE, never replacement storage or an empty database.

`StorageLifecycle.foundationOnly()` is deliberately a no-persistence A1-01 adapter.
A1-02 must replace it with SQLite initialization at <world>/economy/economy.sqlite,
one owned connection, 5-second busy timeout, schema and identity handling. No SQLite
library is required or bundled in A1-01. Add it to both release packaging and explicit
development runtime dependencies in A1-02 and verify real driver class loading.

## Workers and limits

One storage worker, two calculation workers. Waiting queues: 256 storage, 64 calculation.
At most 320 outstanding work futures; completion queue capacity 320. Reject overload
explicitly. Worker suppliers must capture only immutable detached values, never Minecraft
objects. Successful and task-failure completion is delivered on post-tick; immediate
admission failures complete on the caller/server thread. A tick starts callbacks for at
most 1ms. Individual callbacks must be short: this budget cannot preempt a callback.
Never join returned futures on the server thread. No tick waits on storage.

Only stopping may wait: one shared 30-second deadline, close on the storage-owning thread,
then interruption escalation and exceptional completion of outstanding requests. Adapter
close executes exactly once in the thread's finally block, including failed initialization.
A timeout returns false, retains that result on repeated stop and logs an error. Java
cannot forcibly stop interruption-resistant work; adapters must honor interruption and
close within the deadline. No subsequent package may treat a timeout as successful drain.
A1-02 must retain exclusive world ownership until actual disposal, even after timeout.

`RequestContext` is constructed by trusted server handlers: actor identity must come
from the authenticated sender, never payload claims. The server session UUID scopes
requests; correlation UUID ties responses to requests. Transport bounds are 16KiB;
domain services own permissions and semantic validation. No speculative network packets.
`FoundationResponse.READY` never means a durable financial commit.
