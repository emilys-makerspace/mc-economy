## Durable behavior evidence

JournalEngineTest covers atomic two-record+projection+outcome commit, canonical field-order
 equivalence, original request/transaction/sequence/result retained on retry and restart,
 explicit record positions, economic-update reference, changed payload/type conflicts, other
 actor/policy lookup denial, rollback after a projection write, terminal rejection retention
 even if a later handler would accept, and correction-by-append.

Direct SQL fixtures attempted UPDATE, DELETE and INSERT OR REPLACE against all fact tables,
plus late record insertion: all rejected without changing facts. Startup rejects a removed
journal-protection trigger. Supported schema-2 upgrade refuses absent backup, then preserves
UUID and earlier migration timestamps after a validated complete-world fixture backup.

JournalServiceTest admits 50 overlapping same-key submissions before acknowledgment, invokes
the handler/projection once, publishes only on server ticks, and returns one original outcome.
Cache publication failure logs separately and leaves COMMITTED unchanged; repeated submission
has no second effect. Canceling a copied wait leaves accepted work durable and lookup succeeds.
Storage queue overload consumes no ID and a later same-ID submission can commit normally.

Test-only JDBC proxies inject faults before commit, after actual commit but before response,
after postcommit autocommit cleanup, during rollback, and during close/recovery. Confirmed
commits resolve to their original outcomes; confirmed absence permits explicit same-ID retry;
rollback+close failure disables writes and retains the ownership lock. A failed recovery maps
to UNKNOWN/UNAVAILABLE; after confirmed disposal and reopen the original commit is found.

JournalProcessTest launches its own disposable child JVMs and forcibly terminates ONLY those
processes after an instrumented precommit boundary or after commit before external publication.
Precommit death leaves no operation/record/projection effect. Postcommit death preserves the
original result; retry/lookup with the same operation ID produces one durable effect. This is
process interruption evidence, not hardware power-loss proof or an external-delivery protocol.

## Remaining boundaries

No gameplay handlers or fixture projections ship in production. Replay reader performs no
external effects; full replay/recovery orchestration belongs to A1-04, financial rules to A4,
item/external-delivery protocols to A5. Database idempotency does not make external delivery
exactly-once. Canonical normalization is versioned service responsibility, not inferred by
this generic layer. Facts and rejection identities currently retain for the world lifetime.

A privileged DB/software owner can bypass protections by replacing schema/software; current
startup detects missing/altered registered triggers, not cryptographic tampering. Filesystem
and JDBC guarantees remain those verified on macOS. Manual integrated-world play, separate
installed-release loading, real network failures and hardware power interruption were not run.
The client smoke run was intentionally canceled after loading. No EULA was created/accepted;
NeoForge dev behavior bypassed that check. Standard first-run properties/offline/LAN/asset/shader
warnings did not prevent loading or server shutdown.

For journal changes, select journal tests + JournalMigrationTest first, then full build. The
process suite kills only newly spawned fixture JVMs. Schema changes require keeping old
fixture upgrades and pre-upgrade backup gates; never rewrite existing journal meanings.
