# Fixture financial time

A10-05 introduces a trusted session clock for the release-excluded debt composite. Production startup and existing `ServerServices` constructors retain `Clock.systemUTC()`. Minecraft 1.21.1, NeoForge 21.1.252, Java 21, schema53, banking wire10 and public API versions2/1/1 remain unchanged.

`Economy.installFixtureClock(server, clock)` accepts installation only on the server thread before service startup, once per server, with the explicit `economy.debtCompositeProbe` property. The canonical world must be a fresh `economy-debt-composite-<UUID>` below `/private/tmp/economy-a10-05-<suffix>/client/saves`, without an existing `economy` directory. Session cleanup removes the clock. There is no packet, administrator command or game configuration for jumping time.

Startup shares the same clock with `FoundationRuntime.Configuration.production`, `ServerServices` and denomination selection. `financialClock()`/`financialMillis()` supply authoritative ledger quotes, pricing and eligibility, loan and credit capture, FX, debt/report reads, collection presence and payments, and server menu expiry checks. Financial collection reminders and cooldowns share it; the eight-second greeting and entity navigation retain real elapsed/tick timing. Journal audit UTC and queue, callback, shutdown and polling budgets retain their independent real clocks.

`FoundationRuntime.observedDeadlineTurns()` counts actual calls to the deadline dispatcher, including event-completion turns. It is a volatile session observation, not a persisted cursor, child-effect count or readiness override. `ServerServices` exposes the observation for the probe watchdog. The fixture must stop beyond10,000 observed turns or ten real minutes and cannot alter financial semantics to fit those bounds.

The fixture advances a monotonic clock only after normal economic readiness and a serialized read-only boundary inspection. Next boundaries include the deadline provider's next event and fixed systems' frontier plus cadence, excluding values at or beyond their prospective retirement. Calendar diagnostic fixed-system rows alone include retired systems and cannot determine the next boundary. The ordinary production dispatcher, capital preparation and projection draining remain responsible for work and stage order. Native confirmations use the same normal offered-menu protocols and bounded quotes as player actions.

The native default boundary exposed an existing activity observer incompatibility: debt sales register a version2 `ALLOWANCE` institution account, whereas the observer required version1 for every institution account fact. The observer now validates that supported version2 allowance through `DebtFinance.validateAllowanceAccount` and retains its nonspendable treatment. Other unsupported versions and role/version combinations still fail. Finite cash, claims, sale pricing, deadlines and attribution formulas are unchanged.

See [package handoff](../A10/A10-05.md) and [actual evidence](../A10/verification/A10-05.md) for the linked facility, native milestones and limits. External-client testing remains a separate pending manual A10-04 witness and is excluded from CircleCI.
