# A8 production simulation and trader interaction — V49

The production lifecycle loads `SimulationConfig` once from `economy-simulation.properties`, validates all keys, booleans, bounded exact rational values and weight sums, and persists a `SimulationLifecycle.Manifest` with initial configuration, activity manifest, pinned catalog/cash hashes and installed macro provider. Manifest identity/configuration is immutable across restarts; model/rate changes use future journaled control policies. Missing world denomination or source readiness stays explicitly pending. Existing historical worlds retain their complete-world upgrade-backup gate.

After source preparation and world-currency selection, production schedules the existing atomic future A/F/H rate activation. It uses the existing clock/dispatcher and original implementation manifests, preserves captured fixed loan terms and legacy FX history, and never manufactures pre-activation observations. Initial warm-up precedes the first complete financial-day publication. Future operator edits remain chronological, bounded and prospective through `MacroControls`; operator-backed requests record the authenticated player actor. Pause/manual/resume use the existing frozen selected-outcome path. A configuration edit explicitly schedules PAUSED mode and requires a later explicit resume.

`TradeHooks` claims ordinary villagers and wandering traders through the enabled server policy as well as the durable ownership marker, preventing native checkout before asynchronous hydration completes. BankerEntity remains excluded. Claimed ownership remains blocked even if initial feature activation is disabled. Native menu/result/quick-move/extraction/restock/progression guards retain their original protections. Unsupported offers stay unavailable instead of falling back to native checkout.

`TradeRuntime` captures native offers, live workstation/current position and wandering seed on the server thread. Bounded worker continuations synchronize A7 market sources, resolve village/dynamic/wandering identity, capture catalog revisions and install individual stock. Existing offer identities retain remaining stock across catalog extension. Its existing flush barrier, loaded-work tick buffers and relocation logic run before a quote. Entity/market caches and checkpoint submission limits remain bounded.

The custom `TraderMenu`/`TraderNetwork`/`TraderScreen` accept only offered actions with exact connected player/menu/session/revision, live owned trader within six blocks and rate limits. Snapshots have at most16 lines/choices, bounded fields and12KiB payloads. The client chooses offer, quantity, rail, explicit account or cash currency, then quote and confirmation. Prices, balances, bank/provider authority, stock, components and reputation come from server sources. Foreign quotes display conversion and issuer fees. No hidden account fallback, implicit credit or ground drops.

`TraderController` captures detached inventory/native reputation/capacity and maintains revocable live permits. Monetary BOOK/SETTLE uses `tradeMonetaryStorage`, checking cached economic admission and authoritative worker-time currentness; `tradeStorage` remains a distinct trusted maintenance/read path. Gossip is normalized by100, villager Hero benefit by0.05 per level, and original special-price output by original native cost; the signed result is capped at0.25 before the shared joint-spread rule. Native demand is excluded. Equivalent cohorts are bounded and source-revision hashed; incomplete/unrepresentable comparisons refuse before consumption. Original goods/secondary inputs and cash batch quantities use `TraderInventory`; saved HELD proof precedes financial commit. The existing account/cash backends atomically compose money, stock/market transition, semantic activity, output custody and original progression intent.

Cancelling untouched quoted inputs permanently closes the original financial operation before quarantine and marked-lock release; additive `npc-untouched-abandon` evidence validates exact original linkage. It creates no physical return. Independently saved held originals use explicit return claims, with cash locks transferred under the existing cash return protocol. Account returns use the same custody primitives and independently verified evidence. Committed money is never repeated. Delivery requires a fresh one-use capability and independently saved STARTED/DELIVERED witnesses. Claims list bounded retained outputs. Interrupted/ambiguous held/delivery/progression retains reconciliation obligations rather than recreating capabilities.

Native profession/XP progression uses one durable original dispatch. `TradeEntitySaves` invokes the native loaded whole-entity-chunk save on the server thread, observes that exact EntityStorage write future through a narrowly scoped mixin, then independently reads the saved entities region on the storage worker. It searches bounded root/passenger entries and verifies saved trader identity, offers/XP/villager data and progression markers. It never overwrites a chunk with only one entity, blocks on a global save, or treats expected/live NBT as evidence. STARTED proof authorizes one native notifyTrade sequence; APPLIED proof precedes acknowledgment. Uncertain attempts remain ambiguous.

`SimulationDiagnostics` provides cached immutable coverage/baseline, age, mode, A/F/H, config/policy/source identity and numeric limits. Public snapshot/history reads never advance time, seed input or grant money authority. History uses exclusive financial-day cursors and at most16 saved outcomes. `EconomicSimulationIntegration` v1 requires current authenticated ownership grants and exposes no SQL callbacks. `TradePriceSource.EmeraldV1` remains the captured temporary source; A9 replacement needs a future explicit source epoch/fact adapter and never rewrites past quotes or carry state.

V49 appends the immutable production manifest; new source codecs/validators participate in startup, recovery, offline inspection and backup/restore. Existing V1–V48 facts keep their meanings.
