# Financial-day macro rates — V48

`MacroProvider` (`economy:a8/macro-rates`, implementation v1) is installed in production and dormant without `MacroActivation`. It uses the existing financial calendar/dispatcher at stage zero. Its immutable manifest has `00-open`, eleven `01-close/<currency>`, `02-plan`, eleven `10-prime/<currency>`, `20-fx`, and `30-complete`. Pages remain at most16; stable membership lets the dispatcher discover all26 children before its separate completion turn.

`MacroActivation.activate` is a trusted worker API, with no production lifecycle caller in this package. A must be an aligned financial boundary strictly beyond trusted wall, all observed high-water marks and processed/in-flight frontiers. F=A+1,200,000 ms; H is the first original fixed daily end at or after F. One journal transaction commits currency-prime activation/bootstrap, initial control configuration, original-signature legacy retirement and a receipt binding A/F/H to the exact installed stage-zero successor event. Conflicting future legacy prime/FX edits and unsupported existing standalone/partial activation are rejected; history is never discarded. Retry returns the original receipt before new-time admission checks.

Activity must be ready and fully observed by A. Provider source facts v2 explicitly start their horizon at A, retaining older v1 opens/closes and anchors. The first new window may skip only pre-A history, and only after the last old window is completely closed. Its saved firstDay/anchor prove the transition. Subsequent closes are contiguous and retain fourteen indexed day summaries. No missing input becomes a zero observation. Empty complete input is a legitimate hold.

The plan target atomically persists `ActivationModelPlans` automatic input/output and `MacroPlans` selected outcome. The saved input includes source frontier/window hashes, W/B counts, prior primes/FX, activation anchors and immutable configuration UUID/revision. The selected outcome records policy UUID/revision, mode, automatic/input hashes, final prime/FX maps and explanation/hash. Currency/FX children consume that outcome; no child recomputes against partial current publication. The coherent FX vector is one child. The final basket child binds all eleven prime IDs and the FX ID with the prime-completion source in the same transaction. Dispatcher completion is a separate turn. Prime reads and runtime scheduled readiness remain gated through that turn.

`MacroControls` appends immutable future policies, with at most16 pending rows and a captured scheduling frontier. AUTO uses the model; PAUSED holds the captured prior basket while closing current windows. MANUAL supplies full relative APR deltas and FX multipliers normalized to the permanent reference. It requires a completed paused/manual intraday predecessor and validates the entire pending sequence, including six-digit APR bounds/step and all ordered FX pairs after twelve-digit rounding against both prior rates and activation anchors. It rejects invalid requests without clamping. A future pause row alone cannot predict an intervening automatic or legacy daily vector; the caller must wait for the paused basket. A manual row executes once at its effective boundary, then later events hold. Resume must append after all pending rows and uses current W.

V48 adds `macro_activations`, `macro_control_policies`, `macro_rate_plans`, and `macro_rate_completions`, immutable guards/indexes, strict registered facts and startup/recovery/offline/backup support. Activation/retirement source v2 distinguishes the atomic owner; window and prime/FX source v2 require exact dispatcher child operations. Historical source versions retain their former identities and automatic-model meanings. The daily FX index and actual legacy completion correspondence stay unchanged. Fixed-before-domain ordering remains unchanged; when F=H, retirement removes the old fixed candidate and the macro event publishes at F.

A8-07 owns public controls, permissions, diagnostics, menus and production lifecycle activation. These trusted APIs are not packet handlers. Verification is scoped in [A8-06-02 evidence](../verification/A8-06-02.md); gameplay rollout is not implied.
