# Existing administration and reviewed settings

A10-07, 2026-11-09. [Handoff](../A10-07.md), [evidence](../verification/A10-07.md), [operator paths and permissions](../../docs/SERVER_GUIDE.md).

Physical terminal administration retains the existing terminal-owner/operator admission, geometry, reach and session checks. Account ownership remains a separate authority; owning an account does not grant operator commands or another player's terminal. No global administration GUI or new permission model is introduced.

Terminal settings use `configure` to capture a server-held `TerminalSettingsReview` from the displayed snapshot and proposed native currency/cash mode. The bounded review names terminal kind, anchor/dimension, settings revision, currency and every accepted cash denomination/type, including horizontal bills. Preview creates no configuration effect. `configure_confirm` is offered only on the ADMIN review page. Confirmation rereads the terminal and requires the original full snapshot, then submits its original generation/revision through existing live admission and `TerminalPolicy.CONFIGURE`. It never rebases an old draft onto newer state. A changed snapshot produces typed `TERMINAL_STALE` guidance and an explicit read-only Refresh settings action. Brand review also displays terminal scope.

Existing configuration journal requests, original-operation retry and uncertain physical recovery remain authoritative. Refresh/inspection does not advance financial time, mint money or compensate cash. Binding inspection remains a requester-only bounded metadata read: scope, revision, geometry, placement identity, binding/currency/mode/state/catalog revision and unfinished cash-work guidance. Existing audited financial inspection paths retain their bounds and redaction; this package does not broaden their audience or payloads.

FX administration keeps the current one-currency prospective policy and immutable reference rules. New work requires the actual connected operator command source. At most16 pending submissions retain player/services/session identity and a live lease; tick/shutdown revokes new effects on disconnect, death, permission loss or service replacement. Stable actor/kind admission allows original committed receipt lookup before the live editing guard, so revocation cannot erase an already committed outcome. Uncertain results instruct retry with the same operation UUID; configured macro takeover points to existing macro controls.

Covered messages are localized in en_gb, fr_ca and fr_fr. Other subsystem diagnostic formats are retained; this is not an exhaustive command translation claim. Banking transport is12 (new strict allowlisted confirmation action), requiring paired client/server updates. Schema54 was already present at package entry; no storage migration or public API version change occurs here. Banking2, Simulation1, Valuation1 and SimulationHistory1 remain.
