# Public API stability — A10-06

The [integration guide](../../docs/INTEGRATION_API.md) and [signature/lifecycle reference](../../docs/API_REFERENCE.md) describe the supported server surfaces. BankingIntegration2, EconomicSimulationIntegration1 and ItemValuationIntegration1 remain byte-for-byte unchanged from the A10-05 baseline. Their legacy domain/grant exposure remains supported and explicitly disclosed; no class move, removal, deprecation, binary break or saved-data migration is introduced.

One concrete usability gap required an additive value projection: legacy selected-plan history takes an exclusive financial-day cursor but its returned MacroPlans.Outcome has no day field. `ServerServices.simulationHistory()` now exposes independent `EconomicSimulationHistory`1. Its `page(Grant,long,int)` returns `CompletionStage<Optional<Page>>`: denied grants yield an empty Optional, while an authorized empty history has a present empty page.

The worker-only `SimulationHistory.page` performs one read transaction, joining saved window/selected-plan metadata to its immutable journal fact. It filters the current world, sorts descending by financial-day index and fetches at most limit+1≤17 rows. A next cursor is present only when lookahead proves another row; its exclusive value is the last emitted day. No SQL callback is public, and no read advances/observes time, registers sources, repairs projections or promises publication readiness. Selected-only plans retain their historical meaning.

New DTOs use API/Java value types and immutable copied collections. They preserve actual record version1, original world/window/policy identities, day/boundary, exact prime/FX maps, ratio numerator/denominator, input/automatic/outcome hashes and explanations. No repricing, ratio normalization or recapture from current policies occurs. The persisted fact/schema and other facade versions are unchanged.

Admission and worker callbacks retain the existing owner-thread/session/world grant checks and bounded worker/publication queues. Grant authority and live player/menu audience are distinct. The [compile-checked consumer](../../src/test/java/ca/emilybelnavis/mcmods/economy/examples/SimulationHistoryExample.java) acquires a real server-context grant, routes completion through the server executor and suppresses publication after replaced player/service/session/world/view or abandoned display. Cancellation does not undo admitted work.

No unmet concrete event consumer was identified. History and provider publication consumers use existing completion stages; financial consumers use existing atomic journal/register composition and original-outcome recovery. Internal commit observers, lifecycle/reload hooks and storage callbacks remain internal. No event bus, compatibility adapter or new monetary authority is added.

[Handoff](../A10-06.md) and [verification](../verification/A10-06.md) record actual checks and limitations. The [qualified A10 acceptance](a10-acceptance.md) and [downstream handoff](a10-downstream.md) retain these API meanings and unsupported B-series capabilities; no new API/event authority is implied.
