# Core screen layout — A10-03

The supported minimum is a320×240 logical Minecraft GUI viewport. This is a bounded layout contract, not arbitrary-size support. Physical window coordinates and framebuffer pixels may differ on high-density displays; actual scale and logical dimensions are recorded in [native evidence](../A10/verification/A10-03.md).

BankingScreen retains its316×236 terminal and physical deposit-slot coordinates. Persistent header arrows and PageUp/PageDown reach body text and choice pages without a wheel. The footer status is focusable with complete tooltip/narration text. Financial service actions remain server-offered; multi-action credit pages use the existing Actions chooser instead of extending buttons beyond the terminal. Body text no longer has a floating scroll hint over its final rows or form controls. Draft, currency/destination and scroll state survive resize; an incoming revision clears the reviewed capability under the existing review identity/revision rules. Each button also captures its offered revision, refusing obsolete callbacks.

BankerScreen, CollectionScreen and TraderScreen share presentation-only FolioLayout. At minimum they use308×228; at larger viewports they grow up to420×300. Their text region includes complete body and status, with bounded wrapped-row scrolling, visible directional buttons, wheel and PageUp/PageDown. Four offered choices per page occupy a separate2×2 region with previous/next controls. Full labels are available in tooltips and narration. Collection reserves a distinct amount-input row and persistent Exit. No physical inventory slots or financial calculations belong to these folios.

At the minimum folio boundary, body occupies y28–112, scroll controls112–130, choices138–178, optional amount184–202 and footer204–222, relative to its origin. Resize preserves harmless draft, choice page, text scroll and focus when the same capability remains. New menu revisions reset folio navigation; callbacks capture their own original revision. Focus survives navigation rebuilds so keyboard scrolling/paging remains repeatable. Status is part of scrollable content rather than a truncated footer.

Only geometry, focus, scrolling, presentation labels and release-excluded layout fixtures changed. Schema53, banking wire10, other menu wires1 and API versions2/1/1 remain unchanged. Server authorization, amounts, terms, request identity, rails, sources, deadlines and recovery remain authoritative. The native fixture supplies bounded presentation snapshots to real widgets and never confirms a financial operation; prior accounting/service evidence is reused.
