# Item reference configuration and snapshots — A9-02

Delivered 2026-11-08 under the [A9-01 freeze](a9-source-contracts.md) and [shared policy](a9-shared-contracts.md). [Evidence](../verification/A9-02.md) and [handoff](../A9-02.md) record acceptance. Storage is V50; Minecraft 1.21.1, NeoForge 21.1.252 and Java 21 remain pinned.

## Delivered scope

`valuation/ValuationConfig`, `ValuationData` and `BaseValues` implement detached explicit values only. The original runtime `data/economy/valuation/catalog.json` contains the approved 1,333 classifications and 349 CAD base anchors, copied from the approved CSV. The other 760 derived, 109 variant and 115 intentionally unpriced identities retain their classifications. There is no recipe graph, processing/brewing/variant evaluation, public contribution registration/API, source switch or trader activation. Existing commerce continues to use EmeraldV1. Financial wealth/credit valuation is separate.

Optional `config/economy-valuation.json` has `bases` and `overrides` arrays; each entry requires `item`, uppercase `currency`, decimal-string `amount` and positive `referenceCount`. Missing file means empty operator layers; invalid files are never replaced. Config permits at most 4,096 entries/1 MiB, 12 decimal places and 128-bit reduced source numerator/denominator. Counts are 1–1,000,000. Unknown fields, duplicate JSON keys/identities within a layer, unknown registry/currency identities, operator-only prices and nonpositive/oversized values reject the whole candidate. Base/override overlap is intentional precedence. Mod IDs require a trusted contribution claim before operator entries can refer to them.

Source order is server override, server base, contributed base, built-in base; missing sources remain unavailable. Trusted internal `Contribution` data has provider identity/revision, namespace-owned claimed IDs and explicit bases. Duplicate providers/overlapping claims reject deterministically even if amounts match and even under an operator override. Providers are sorted; removal changes manifest identity. The live lifecycle currently installs no providers. Public authentication/registration, exact selectors and derivation opt-ins remain A9-04 work; no specific integration is present.

`Inputs` captures the complete item registry plus recipe/tag/feature hashes. `Manifest` retains complete catalog/config/contribution/source data and hashes, canonical version/algorithm, and source provenance. Strict canonical decode reconstructs and validates all derived provenance, without consulting a newer catalog resource to reinterpret historical data. Same canonical content hashes identically; changed content cannot reuse its snapshot identity. A prospective reversion to historical content receives a new publication revision/UUID.

## Exact arithmetic and internal reads

Source prices are exact rational minor units per item (`amount × currencyMinorPerMajor / referenceCount`). Target conversion uses one captured `EffectiveFxSnapshot`: source rate / target rate and the registered minor-unit ratio. BigDecimal rates become exact rationals; bounded internal values are at most 4,096 bits. Publish positive unit minor amount with HALF_UP and minimum one; checked multiplication produces quantity totals. Overflow/missing FX/missing inputs return no partial spendable amount. Free water is a typed internal input with zero cost, not a zero-valued item/config fallback.

A plain-item value does not strip component state. Nonempty component identities reject; named VARIANT rows reject even under a plain override until the corresponding adapter exists. Explicit operator prices can terminate ordinary DERIVED rows without implementing a recipe. Unregistered mod items, operator-only items and missing derived sources stay distinct.

`ValuationRuntime` has package-internal cached/asynchronous base-read seams and immutable cached status; no public `ItemValuationIntegration` is exposed. Current admission atomically captures readiness, resource epoch, snapshot and generation under the publication gate. The storage worker resolves captured-time FX and rechecks generation. Retained requests require an explicit saved FX UUID and retained snapshot UUID. They never apply current FX to old data or advance economic time. Results retain manifest/config/source/FX identities; the internal wrapper adds publication UUID and capture/publication times. Public grants, request/result shapes and consumer outcome persistence remain their later owners' responsibility.

Root-result cache is an LRU of at most 10,000 entries keyed by snapshot/FX/item/components/quantity/currency. Compiled cache keeps active plus at most 16 historical manifests. Expensive historical decode/evaluation happens outside cache monitors on the worker; server-thread cache reads only perform bounded lookups. Eviction does not delete history.

## Lifecycle and source capture

`Economy.starting/tick/stopping` installs a per-server session and uses the existing bounded `ServerServices.calculate` and storage worker. Startup waits for foundation readiness, captures live inputs, prepares/validates a detached candidate, and only then publishes. Startup with matching persisted content reuses the existing publication without a write. Restart with changed input content creates a new manifest before fresh valuation becomes ready.

`valuation.mixin.ServerReloadMixin` wraps the pinned `MinecraftServer.reloadResources` with existing bundled MixinExtras (no new dependency). Invalidation is synchronous at method entry, including off-thread calls, and covers synchronous exceptions. Completion is handled after vanilla resource installation/tag rebinding. Overlapping reloads remain pending until all completions; an older successful install that finishes last cannot be silently ignored. A ready resource-object mismatch also invalidates on tick. Failed reload without installation can restore matching old readiness. A failed/partially installed overlapping batch may conservatively remain unavailable until a new successful reload; no stale value is admitted merely to restore availability.

Server-thread capture detaches item keys and expanded tag members, hashes selected raw recipe JSON content with strict UTF-8 plus installed recipe ID/class inventory, and records enabled feature names. Limits include 100,000 items/recipes/tags, 4,096 members per tag and 32 MiB recipe source/tag character budgets. No mod serializer/assemble/remainder callbacks execute to establish a base-only recipe epoch. Direct programmatic recipe-manager mutation outside the supported resource-reload lifecycle is not a supported publication trigger. A9-03-01 will add trusted detached recipe semantics/content to a new manifest algorithm version rather than reconstruct historical recipe graphs from hashes.

Candidate generation and final pointer commit share `ValuationStore.Gate`. Superseded work cannot publish or restore readiness; callback readiness updates also check the gate. Invalid config/candidate/publication retains the prior durable active snapshot but fresh valuation remains unavailable until a valid matching publication. This readiness is not yet consulted by existing traders because A9 source activation is unimplemented. Stop invalidates outstanding work and drops the session before existing worker drain/shutdown.

## Journal persistence and recovery

`ValuationStore` adds V50 immutable `valuation_chunks`, `valuation_manifests` and a mutable validated `valuation_active` pointer. Registered v1 facts are `economy:a9/valuation-chunk` and `economy:a9/valuation-publication`. Existing journal limits stay unchanged: 16 KiB record, 64 records and **128 KiB aggregate record payload per transaction**. The earlier generic 1 MiB query limit is not a journal commit limit.

Manifests can be 32 MiB, so publication is two-stage: immutable 8 KiB raw/Base64 chunks in deterministic batches of eight, each separately journaled, followed by full ordered-content/hash/canonical validation and one small atomic publication-header/active-pointer transaction. No uncommitted candidate is active. Final transaction uses the current predecessor revision and generation gate; large decode/reassembly stays outside that gate. Chunk operation IDs depend on world/content/batch; publication IDs depend on world/revision/content. Original journal lookup handles uncertain commit outcomes and same-content retries. A9-05 must extend the final atomic publication to already-enabled source scopes; none exist now.

All published manifests and stages remain retained. Accounted quota is the sum of accepted publication canonical sizes (including reversion publications) plus chunks for never-published content; cap 256 MiB. This is a canonical-data quota, not a cap on SQLite/index/journal disk overhead. Quota exhaustion rejects publication without deleting history. Interrupted staging can consume quota and remains retryable with identical content; there is no automatic garbage collection or maintenance escape hatch. Operators retain backups; future retention maintenance requires its own scope.

On initialize/recover, validate exact schema protections, chunk encoding/order/size/full content hash/canonical payload, world linkage, contiguous publication/predecessor/time chain, latest active pointer, journal fact cardinality and exact projected fact payload provenance. Incomplete staged content is preserved but never considered a snapshot. Queries page at most 32 chunks, staying within existing row/byte limits. Old manifests are loaded asynchronously and remain self-contained; consumers in later packages must retain their original result and selected explanation, not recompute a receipt with new inputs.

V49→V50 requires the existing stopped complete-world backup gate. `WorldBackup` now admits schema 50 in its restore compatibility list; no restore overwrites a destination. All earlier financial tables/history are retained; this migration adds valuation structures only.
