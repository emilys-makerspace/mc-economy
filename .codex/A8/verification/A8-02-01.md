## Implementation and source review

- `ActivityClassifier` reads trusted same-commit domain facts and bounded pre-state. Register COMMIT wins over its embedded merchant CAPTURE; credit-funded register checkout still supplies goods principal. Refunds name the original capture. Loan/card repayment uses actual allocated principal; collection payment compares original versus committed principal. Interest, fees, limit changes and creditor write-offs are not principal flow.
- Generic FX, loan-disbursement FX and deposit/withdrawal previews supply source and actual target principal plus captured publication. Internal treasury/rebase conversions remain neutral. SameCurrency operator adjustments identify real account creation/removal; arbitrary ISSUE/REDEEM postings do not. First accepted unmarked operator cash is separate from neutral marked cash representation.
- `ActivityStore` appends its batch to the original source commit, preserving its result. All source financial effects, observations, counters and changed capacity snapshots share one transaction. Replayed original outcomes bypass the observer. Checked sums and SQLite integer constraints prevent overflow/promotion; unknown relevant source versions fail before effects.
- `ActivityRuntime` chains after PricingAdmission and DepositYield in FoundationRuntime, including later startup servicing. Source initialization and <=16-row capacity seeding finish before READY. Partial activation-day coverage is explicit. Observer setup does not install a new deadline provider.
- Capacity is actual registered CASH above applicable base-currency floor, zero for recognized unpaid dated yield; excludes reserves, claims, customer deposits, treasury/depositor accounts and collection-only Waystone. Recompute only affected banks/currencies using planned posting and final claim overlays. A partial index supports CASH-only bootstrap rather than traversing all synthetic customer financial accounts.
- Capacity histories use source journal sequence as a same-millisecond ordering key, not random operation UUID. This was found during review and protected with two real same-time cash transfers. Both per-account and aggregate history carry exact source sequence; validators verify it against the linked journal transaction.
- V1 codecs enforce 32 observations/275 capacity identities, while the existing individual 16KiB fact and 64-record/128KiB transaction bounds remain authoritative. Oversized/overflowing source compositions reject atomically; no partial counting. NPC counter kinds are declared without an emission adapter.
