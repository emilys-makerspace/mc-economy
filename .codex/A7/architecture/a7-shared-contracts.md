# A7 shared contracts — revision 1

A7-01 contract freeze, 2026-11-06. These are implementation requirements, not installed Java APIs or schema allocations. [Approved policy](../../architecture/planned-a7-a10.md) controls gameplay; [evidence](../verification/A7-01.md) distinguishes source proof, resource observations and remaining implementation witnesses. A7-02 may implement persistence/admission; A7-04 must demonstrate physical generation before claiming it works.

## Generation boundary

Use a registered composition structure type, not a subclass of final `JigsawStructure`, pool weighting or a chunk-load village discovery scan. Replace only the five `minecraft:village_{plains,desert,savanna,snowy,taiga}` definitions under their existing registry keys. Keep vanilla structure-set entries, weights, placement, biome holders, spawn overrides, generation step and terrain adaptation. Existing village/locate tags continue to address those same keys. Codec revision 1 contains the original full `JigsawStructure.CODEC` value and wrapper settings; require identical settings before accepting it. NeoForge structure modifiers must affect the outer settings used by `Structure.generate`; do not independently reapply them to a delegate. Delegate `findGenerationPoint(context)` once with the original context; retain position, empty result and biome validation. Materialize `GenerationStub.getPiecesBuilder()` exactly once, copy original pieces in order, then append only A7 pieces. Never consume the delegate/context random stream for A7 selection. Return the original position and augmented builder before `Structure.generate` builds its `StructureStart`.

Register the wrapper type and every custom piece loader before registry decode/start loading. Pinned PiecesContainer.load logs and skips unknown/corrupt children; reconciliation must check the entire captured manifest and fail closed on missing children, never infer completion from a surviving subset. Use a metadata piece at the original start for supported nonzero non-abandoned plans, including pending plans; it performs no financial work. Bank/path pieces have independent versioned loaders, full bounds and immutable manifests. Preserve vanilla piece instances, junctions, rotations, ground deltas and serialization. `StructureStart.createTag/loadStaticStart` retain the original structure registry key and references. The wrapper delegates `afterPlace` to the original jigsaw implementation (currently inherited no-op). Existing saved vanilla starts load unchanged and are never retrofitted.

Datapack boundary: support the pinned vanilla definitions, pool graph, template content and processors only. Capture a resource fingerprint revision. Replaced structure definitions can override the wrapper and therefore opt out; never restore it by force. Replaced or unknown templates/pool elements/processors produce `UNSUPPORTED_RESOURCE` with no A7 physical content, rather than guessing a building count or whether a start is abandoned. No claim of modded-village compatibility. Diagnose missing wrapper definitions once per resource revision. See [content inventory](a7-template-inventory.md).

`ChunkGenerator.createReferences` searches start chunks within eight chunks in X/Z. Every appended physical piece must have all covered chunks inside that square relative to the start chunk, in addition to the approved distance limits. Search sites through the full 96-block boundary band but reject those outside reference reach with `REFERENCE_REACH`; aggregate this in pending diagnostics. Do not extend vanilla reference scans or silently place unreferenced pieces. A metadata-only pending branch remains discoverable at its start. This technical constraint can increase pending outcomes; it does not change the approved maximum search distance or promise universal placement.

Generation threads use registry/template/noise-generation inputs and an immutable server-published planning snapshot only. No JDBC, waiting, server-level chunk access or worker callbacks. Publication contains denomination and revision, catalog/readiness revision and eligible providers; no balances. Atomically read it once after original layout materialization. If absent, save `CAPTURE_PENDING` metadata with layout/resource inputs; generation continues normally. First ready server reconciliation captures denomination/providers exactly once by compare-and-set, recording the effective snapshot revision. This is an explicitly delayed capture, visible in diagnostics; it never pretends to know the denomination at unavailable generation time. A captured plan never recaptures on reload or denomination change.

## Classification and original geometry

Count the original selected `PoolElementStructurePiece` instances using the fingerprinted inventory, before any A7 additions. One included piece contributes one, regardless of its weight, rotation or repeated template identity. A supported composite contributes at most one only if its reviewed content describes one building; revision 1 accepts no unreviewed composites. Empty elements, roads, terminators, farms, wells, pens, stables, decorations and town centers contribute zero. Reviewed pinned decoration feature elements count zero; unmanifested feature/unknown elements fail closed for A7 planning. Detect abandoned status from the selected root element's reviewed zombie town-center template, before counting or planning. Unsupported root means `UNSUPPORTED_RESOURCE`, never normal by default. Abandoned and zero-count starts receive no A7 pieces, markers, branch slots or staffing; diagnostics may report the exclusions without world writes.

Original boundary B is the inclusive X/Z rectangle union of **all original selected piece bounding boxes**, including roads, farms and excluded buildings. It is captured before A7 additions and never expanded for measuring later branches. Also retain each original 3D piece box and jigsaw junction as preservation obstacles. Original Y bounds do not define village size. Entrance distance is horizontal Euclidean distance from the center of the entrance threshold block to the closest point of the continuous rectangle formed by B's outer block faces. Compare squared distances, no rounding: interior=0, nearby=(0,32], farther=(32,96]. The whole reserved bank envelope must be inside B for an interior candidate. An exterior site's entrance must be outside B; any envelope overlap with an original obstacle rejects it. Reservations for all chosen branches/path corridors participate in later collision checks.

## Bounded site and path search

Technical defaults revision 1, distinct from approved gameplay numbers: deterministic grid spacing 4; candidates on that grid plus original road junction offsets, in stable distance/X/Z/facing order, purpose-stream rotation of ties. Budget 256 interior, 256 nearby, 512 farther candidates **per branch**, four rotations each; at most three branches. No safe candidate within a budget means pending `SEARCH_BUDGET`, not proof that the world has no safe site. Reserve required slots before optional slots; a pending required slot does not reroll a successfully placed sibling. Capture candidate index, tested bands, rejection counts and search revision. All candidate envelopes must avoid original piece boxes expanded horizontally by one, except a path's exact road endpoint connection. A path may abut but never replace the original road/junction block.

Sample every footprint/support column and path cell with `ChunkGenerator.getBaseHeight/getBaseColumn` and the generation context's height/random-state inputs. This samples base terrain, not a final-world clearance guarantee. Piece placement must revalidate actual cells in its current generation chunk; later server retries have stricter preservation rules below. Floor elevation is the rounded-down median of sampled surface heights. For each column, leveling depth is the number of solid blocks removed above the chosen floor support plane, maximum 3; foundation depth is the number of new support blocks below the floor down to an existing full sturdy non-fluid block, maximum 6. Floor itself does not consume the foundation allowance. Reject void, fluid support, block entities, non-natural blocks, protected original pieces, unstable falling support and world-height overflow. Never tunnel/remove an overhang to satisfy the allowance. Natural cut/fill uses an explicit versioned allowlist (soil/stone/sand/snow only after stability checks); no generic replaceable-tag permission to clear player work.

Path: 3-wide walking surface, 3 air blocks clearance, connection to a captured original road endpoint. Bounded A* over X/Z cells, 4096 expansions, maximum 256 centerline steps, stable neighbor order and stable cost/tie rules. Stair rise at most 1 per horizontal step, 3-wide supported steps, level landing of at least 3 blocks before turns. Bridge: at most 5 unsupported horizontal blocks over water, 3-wide deck, railings, sturdy abutments at both ends, no lava, no floating piers or boat-route guarantee. Supports obey the same 6-block depth; cuts obey 3-block limit. Reject failed path along with its bank site. These conservative defaults require A7-04 physical terrain witnesses; no pathfinding success or collision-free world placement is claimed from source review.

## Identity and deterministic capture

Canonical identity encoding v1 uses the argument order listed below: strings are unsigned 32-bit byte length + UTF-8, world seed is signed 64-bit big-endian, chunk coordinates signed 32-bit big-endian, UUIDs raw 16 bytes, slot/anchor indexes unsigned 8-bit, effect versions unsigned 32-bit; stream counters are unsigned 64-bit big-endian. Hash input begins with the length-prefixed domain. Reject strings over 128 bytes and slot indexes outside the captured manifest; reject duplicate/oversize/unknown mandatory fields. Hash with SHA-256, truncate first 128 bits for UUIDs with explicit version/variant bits (v8). Do not use Java `hashCode`, collection order or shared Minecraft randomness. Selection seed = hash(domain `economy:a7:selection:v1`, world seed, dimension key, original structure registry key, start chunk X/Z). World UUID is excluded from selection, included in durable identity. Village ID = hash(`economy:a7:village:v1`, authoritative WorldId, dimension, original structure key, start chunk). Before WorldId exists use that tuple as a provisional source key, never create a substitute financial world UUID. Branch ID = hash(`economy:a7:branch:v1`, village ID, slot); anchor generation and operation IDs add anchor slot/effect/action version. Separate SHA-256 counter streams for optional-roll, institution/slot, site/slot and decoration/slot. Bounded uniform draws use rejection sampling of unsigned 64-bit hash words; optional rolls draw integer [0,99], <25 medium, <50 large. Sort eligible provider keys lexically before drawing. Persist selected values, not only the seed.

Slot 0 = required local compact/larger by size. Slot 1 = optional compact for medium, required larger for large. Slot 2 = optional compact for large. Empty optional slots retain the roll and `NOT_SELECTED` or `NO_DISTINCT_PROVIDER`; they never renumber siblings. Local eligibility: catalog `enabled && customerBank && tier1 && BANK_ACCOUNT`, native currency equals captured denomination. Additional eligibility: enabled customer bank with BANK_ACCOUNT and an installed account-admission capability; Tier2-only remains specialist at customer admission. Prefer unused foreign-native entries, then unused local entries. Internal lender/collector entries are never candidates. If a required slot cannot be filled, retain `PROVIDER_PENDING`, full captured candidate set/reason, and report A7 generation not ready; existing banking and vanilla generation continue. Optional provider exhaustion omits only that slot. Automatic queue/restart reconciliation never rerolls. Operator provider retry may complete unfilled required slots from a newly captured eligibility revision, retaining denomination, existing choices and the same per-slot stream; record both revisions explicitly. Do not silently substitute a different denomination.

## Detached interfaces and serialization

Names below are frozen responsibilities/signatures for implementation, not existing symbols. No DTO carries Minecraft objects or callbacks across the storage boundary.

| Interface/value | Contract |
| --- | --- |
| `PlanningSnapshotV1` | denomination/code+revision; catalog/resource/policy revisions; sorted eligible provider entries; readiness reasons |
| `VillagePlanV1` | provisional source tuple; optional WorldId/village ID; algorithm revision; original count/style/abandoned result; original boxes/junctions; capture status/snapshot; slots; bounded diagnostics; canonical payload digest |
| `BranchPlanV1` | branch/slot/required/size; institution/native currency; template fingerprint; transform/entrance/reservation; service and desk anchor lists; placement attempt revision; per-chunk manifests and states |
| `observePlan(plan)` | server-thread loaded source observation to bounded storage reconciliation; returns original registered plan or conflict, never a replacement plan |
| `activateBranch(request)` | branch/plan digest/revision; exact anchor generation/kind/geometry/institution; expected terminal revision; original operation ID and detached live lease; returns COMMITTED, REJECTED(code), UNKNOWN(original ID), NOT_READY |
| `observeBranch(observation)` | loaded-only geometry/generations/desk/entity observations at a server tick; worker updates using expected revision; unloaded is UNKNOWN, never absent |
| `retryPlacement(branch,revision,operator)` | one explicit pending attempt, preserves choices; rejects removed/uncertain/active branches; records authorization and result |
| `setStaffingPause(branch,revision,paused,operator)` | idempotent revision-checked persisted pause; freezes timer, no financial authority |
| `StaffSlotV1` | branch/desk slot; desk generation/revision; assigned entity UUID; assignment revision; vacancy evidence; elapsed ticks; pause; reserved replacement UUID/operation; spawn status |

Generation-local NBT envelope `economy:a7_plan` version1 contains the detached source plan and digest; registered metadata piece loader preserves it in `Children`. Cap 256KiB encoded plan, 1024 original pieces, 3 branch slots, 2 service and 2 desk anchors per branch; overflow becomes `PLAN_LIMIT` exclusion metadata with source key and diagnostic counts. Unknown newer versions are preserved opaque and never activated/rewritten; malformed digests produce `PLAN_CONFLICT`. The original structure reference remains vanilla-sized for metadata-only plans. Physical pieces include their full extents before reference creation.

Once the containing start is saved, the source plan survives independently of economy readiness; reconciliation reads only already loaded starts/markers, at most 4 observations/tick, bounded 256 in-memory queue. Queue overflow leaves persistent metadata untouched for reobservation on load. Store acceptance is idempotent by world/source tuple+digest; mismatches quarantine, never overwrite. SQLite is the authoritative branch projection/journal, not a second financial store. Metadata is a generation/physical outbox, not an account database. A crash before vanilla saves a new start can regenerate it with the current publication; no stronger cross-store atomicity is claimed. After capture is durably registered, a mismatching regenerated source is conflict, not recapture.

## Lifecycle, placement and removal

Village capture and each branch have independent progress. Branch states: `CAPTURE_PENDING`, `PROVIDER_PENDING`, `SITE_PENDING`, `RESERVED`, `PLACING`, `PHYSICAL_COMPLETE`, `ACTIVATION_PENDING`, `ACTIVE`, `REMOVED`, `CONFLICT`. Record reason+revision on every transition. An active sibling stays active while another slot is pending. Terrain search exhaustion becomes `SITE_PENDING`; no automatic terrain retries. Readiness/queue recovery can reconcile existing evidence automatically but cannot initiate a new terrain attempt.

Initial construction uses registered, chunk-clipped pieces in vanilla `StructureStart.placeInChunk` during FEATURES, not deferred chunk-load building. Keep immutable intended block manifests and per-chunk progress receipts; each `postProcess` may write only within its supplied chunk box. Original layout pieces remain first; every bank/path envelope avoids their captured boxes. No JDBC/worker authorization is required to construct presentation blocks in this generation-only window. Kiosk blocks are born disabled and have deterministic anchor generation IDs; financial activation waits for loaded server reconciliation. Piece NBT captures operation/manifest identity before placement; chunk-local receipt markers and matching cells prove physical completion after chunk save. A7-04 must demonstrate actual chunk save/load and receipt handling before release.

Source preflight reserves complete bank/path envelopes, bounded natural cuts/foundations and required slots before appending pieces. A missing safe site adds metadata only, SITE_PENDING. At actual chunk placement, revalidate natural/clearance cells within the clipped box. Unexpected obstruction aborts that fragment without overwriting it, records conflict; never claim a partial branch active. Original building counts are unaffected. Chunk progression, not repeated `afterPlace` callbacks, owns initial structure effects. Do not run initial `postProcess` from load reconciliation or operator retry.

Later operator retries are server-thread, loaded-only and require all affected chunks FULL with a fresh plan/revision lease. They never force-load. Because original player provenance cannot be inferred from natural-looking block equality, retries are strictly additive: place only in air, never remove/replace an existing block (including grass, snow, plants or fluids), and never carve/level existing terrain. Support may use existing sturdy surfaces without changing them; reject occupied envelope/clearance and player service blocks. Paths connect by abutting an existing road, never rewriting it. This is a conservative safety subset of the approved allowance for modest leveling, not permission to overwrite player construction. Search exhaustion or an otherwise viable site needing cuts remains SITE_PENDING with RETRY_REQUIRES_TERRAIN_CHANGE. Capture full before-images; revoke the server lease immediately on any changed cell before worker acknowledgement. A7-04 must bound physical writes and use the same conservative conflict handling as initial construction.

Crash safety is deliberately conservative: **do not automatically replay missing blocks from a PLACING manifest**. Minecraft chunk saves and SQLite commits are not atomic. If every loaded chunk has matching completion evidence and intended cells, finalize PHYSICAL_COMPLETE. If the source chunk has not reached FEATURES, its ordinary initial chunk pipeline may still run; server reconciliation cannot impersonate it. An interrupted/ambiguous partial write becomes CONFLICT with original operation and observed chunk receipts, remains disabled and requires explicit operator resolution; it is not terrain-pending and `retry` cannot rebuild it. Even matching after-images without completion provenance do not authorize filling absent cells. This prevents a player removal during a crash window from being treated as incomplete construction. No rollback deletes blocks after uncertain placement. A7-04 may only improve automatic recovery with demonstrated provenance, not assumptions about block equality.

After PHYSICAL_COMPLETE, any observed loss of a service generation, desk or building is damage/removal, never permission to replay structure pieces. Persist tombstones outside the removed block. Shell damage alone does not alter accounts or necessarily disable intact kiosks; anchor integrity controls each access point independently. Missing kiosk/desk stays missing. Replacing a player-placed block does not revive a generated generation. Whole branch REMOVED retains IDs/history; no automatic rebuilding. The metadata piece's `postProcess` is metadata-only/idempotent. Bank pieces are initial generation effects only; server reconciliation never calls them to repair missing blocks. Generation of an actually missing region is outside the normal reload guarantee and conflicts with a surviving durable branch record, rather than authorizing a replacement branch.

Trusted activation is a new **internal** adapter through `TerminalPolicy` placement and `TerminalBanking` native binding, not `TerminalLifecycle.setOwner` with a synthetic PlayerId. Use typed branch/system principal, retaining legacy player owners; A7-02 must extend owner admission explicitly and preserve existing player operations/encodings. Generated anchor activation may place/bind only its captured branch bank; no CONFIGURE-anywhere, rebranding, capital/account creation or general operator authority. Preserve custody blockers, exact terminal revisions and original journal outcome lookup before any resubmission. Until committed and freshly observed, hardware is policy-unready. UNKNOWN retains exact intent and operation; never allocate a replacement ID to escape uncertainty. NPC routing obtains fresh `KioskAdmission` with actor/session/reach/anchor/permission/action/revision checks; appearance, assignment and dialogue are not authority.

Player construction preservation: original layout boxes are protected even for excluded pieces. Initial effects occur only in each chunk's ordinary generation pipeline, with existing original boxes and exact current-cell preconditions. Loaded-world retry uses the additive-only rule above; no generic replaceable tag or matching natural before-image proves player ownership absent. Restart never turns an ACTIVE/PHYSICAL_COMPLETE branch into a placement candidate. Operator retry cannot clear an obstruction or rebuild REMOVED/CONFLICT branches.

## Staff and command boundary

No staffing implementation in A7-01/02/04. Template desk slots do not depend on banker classes. A7-05 implements entity admission using branch+desk generation and persisted assignment revision, at most one live/reserved employee per slot, one compact/two larger. Work/wander/rest goals remain within loaded navigation around the branch; no merchant offers. Desks may suspend assignments without changing financial entities.

Vacancy needs positive death/removal or authoritative persistent entity-removal evidence; absence in a loaded chunk is insufficient if the assigned entity may have unloaded elsewhere. UNKNOWN freezes progress/spawn. Increment elapsed by one for each observed running-server tick with an active loaded branch, valid vacant desk, confirmed missing employee and no pause; clamp to 24,000. Offline, unload, unavailable observation, invalid desk and pause add zero; sleep/daytime jumps add no extra ticks. Persist elapsed checkpoints via storage, and on stop drain using existing lifecycle. Crash before checkpoint can lose uncommitted progress, never gain it; record this bound (maximum 200 ticks per checkpoint). Pause acknowledgement must commit accumulated ticks and paused state before reporting success. Resume retains elapsed and performs fresh checks. At threshold reserve one replacement UUID/operation durably before spawn; mark entity with assignment identity; after uncertain spawn reconcile that UUID loaded-only, never spawn another because it was not observed. Restart restores reserved identity and saved elapsed; removal invalidates lease immediately.

Operator command contract: `/economy branch status <id>`, `/economy branch list [after <id>]` (max16), `/economy branch staffing <id> pause|resume`, `/economy branch retry <id> <expectedRevision>`. Console or authenticated permission-level-2 operator; no client-supplied branch grant. Status shows captured denomination/provider/resource revisions, per-slot states/reasons, placement attempt/original operations, loaded/unknown service/desk state, timer/pause. Retry applies only SITE_PENDING/PROVIDER_PENDING, rechecks current terrain/provider requirements and journals the actor/revision, never forces chunk loads or rebuilds REMOVED/CONFLICT. No account balances/private customer data. Command reads are bounded/indexed and write commands require durable acknowledgement; no global scan or repair-all. A7-02 implements status/provider state; terrain retry stays unavailable with an explicit reason until A7-04 installs placement.
