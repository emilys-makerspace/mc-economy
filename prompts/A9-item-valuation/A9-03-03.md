## Outcome

Implement frozen exact-component identity and supported variant rules. Add compatible premiums once; apply additive 25% discounts per distinct vanilla curse before remaining/max durability. Names add zero without suppressing other properties. Stored enchanted books use ordinary book value plus stored premiums, not double-counted applied enchantments. Enforce supported levels/applicability; unknown components remain unavailable rather than being stripped or ignored.

Value containers as empty object plus recursively valued contents under frozen nesting/work bounds. Apply damage/curse modifiers to the individual object, not all contents; count each container once. Use acquisition-priced non-item content identities such as milk/lava and explicit free water. A potion's brewing total already includes its bottle. Missing content makes the result unavailable. No arbitrary custom component callback or automatic mod-item support.

Use one immutable valuation/FX snapshot and bounded provenance; apply HALF_UP/minimum rules at the frozen publish boundary. Valuation does not execute returned-container recipes or broaden trader predicates automatically. No public SPI, financial eligibility or trader activation.

## Acceptance and handoff

Use a meaningful enchanted/damaged example and a nested-content example protecting modifier order and no double counting. Reuse approved premium and brewing evidence; avoid permutation tests mirroring every table entry. Follow [verification scope](../../.codex/VERIFICATION.md): at most one useful focused named-test invocation and ordinary runnable delivery commands once; no full-suite gate.

Publish `.codex/A9/A9-03-03.md`, identity/container architecture and scoped evidence, stating supported component limits. Preserve pinned versions and registered working client/server development runs. Stop before A9-04.
