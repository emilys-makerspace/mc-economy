## Outcome

Publish immutable server reads and typed contribution API/SPI: exact identity, rounded unit/quantity values, currency/FX identity, snapshot/configuration/recipe/provider versions, structured availability and bounded provenance. Respect lifecycle/thread/backpressure limits; reads grant no money, financial qualification or settlement authority.

Accept explicit values and opt-in supported derivation/variant data for mod items with validated provider identity/revision. Reject conflicting claims atomically; server overrides remain highest precedence. Registration/removal publishes a new snapshot. No built-in mod prices, automatic unregistered recipe values, arbitrary journal/storage-worker callbacks or specific integrations. Internal manifest ingestion already belongs to A9-02.

Add bounded operator diagnostics and user documentation. Unsupported ordinary trader listings stay disabled without player-facing explanation; API/operator reads retain reasons. Coverage summaries distinguish vanilla registry support, operator-only exclusions, component limits and intentionally unregistered mod items.

## Acceptance and handoff

Demonstrate a consumer base-to-recipe/variant-to-foreign-value path plus contribution conflict/removal/reload behavior, reusing existing evidence where unchanged. Document a generic registration example, not a specific integration mod. Do not duplicate upstream tests in a new fixture layer.

Follow [verification scope](../../.codex/VERIFICATION.md): at most one useful focused named-test invocation and ordinary runnable delivery commands once; no automatic full suite/repeated game gate. Publish `.codex/A9-04.md`, API architecture, scoped evidence and A10 read-only handoff. Trader activation remains A9-05/06. Preserve pinned versions and registered working client/server runs.
