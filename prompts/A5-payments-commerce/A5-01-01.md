# A5-01-01 — Payments scheduling and configuration

Status: approved for separate invocation. Execute only when explicitly selected
and the prerequisite handoff is verified.

Prerequisite: A4-06. Read its handoff and the relevant approved rules and
coverage rows in [the A5 plan](PLAN.md) and [shared contract](contract.md). Use the project workflow and scoped
verification guide. Target Minecraft 1.21.1, NeoForge 21.1.252 and Java 21.

## Scope

Implement invoice, merchant grants, authorization, capture, cancellation and refund via the trusted journal. Full capture and one full refund, same currency, zero fee. Bind a persisted five-minute deadline including downtime. Reject capture at the deadline even before bounded expiry releases the hold. Define backward-clock handling. Compose hold transition, postings, invoice and receipt in one commit, preserving standalone hold behavior. Underfunded refunds must remain retryable with original intent. Exclude custody and UI.

Use server-side admission, world-scoped persistence, bounded worker jobs and
server-thread Minecraft callbacks where applicable. Preserve canonical intent
and original operation IDs across retry. Keep the existing ledger and account
contracts available to callers.

## Completion gate

Check duplicate/conflicting intent, deadline and restart, live authority, underfunded retry and rollback on injected receipt failure.

Record checks and limitations in `.codex/A5/verification/A5-01-01.md`. Update
the project index and write `.codex/A5/A5-01-01.md` with the delivered contracts and
next-package needs. Stop at this package boundary.
